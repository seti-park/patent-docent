# drop 신호 (D4 · 2단 — 재정 P-A)

## 1. 조기 — 맹검 스크리닝 메모 (상신 없음 · 진행 계속)

`read-a`·`read-b` 가 **각자** 쓴다. 둘 다 싣는 이유는 두 독립 관찰의
일치/불일치 자체가 신호이기 때문이다(재정 P-U4). 이 메모는 최종 서사 평가
레인(`synthesize`)에 전달되지 않는다(앵커링 방지).

| 실행 | 방향 | 근거 요지 |
|---|---|---|
| `read-a` | `clear` | 「AI 비서가 나와의 과거 대화를 기억하고, 잊으라면 잊는다」라는 한 문장으로 전달되는 소재이며 종속항의 remember·forget·타이머 삭제·기억 통합·설정 변경 API 가 일반 독자에게 익숙한 장면을 준다. 다만 독립항 1 은 메모리 조회 후 모델 입력이라는 매우 넓은 골격이라 「무엇이 새로운가」 축은 접지 뒤 재확인이 필요하다. |
| `read-b` | `clear` | 권리 관심이 '대화를 기억했다가 다음 질문에 쓰는 AI 비서'라는 한 구성에 뚜렷하고, 기억하라·잊어라·일정 시간 뒤 잊어라(CL-8~10) 같은 종속항이 일반 독자에게 바로 와닿는 서사 재료라 안도감 있는 스레드가 설 것 같다. |

## 2. 최종 — 포지셔닝 확정 후

| 시점 | 판정 | 사유 |
|---|---|---|
| 포지셔닝 확정 후 | `go` | 대화형 에이전트가 사용자별 기억을 쌓고·잊고·정정하는 구조는 일반 독자가 자기 경험(같은 말 반복 입력, 잊어달라는 요청)에 바로 잇댈 수 있어 안도감 서사가 성립한다. 성능 수치는 없으나 구조적 차이(사용자 발화로 만든 기억 객체 · 지원 기록 · 만료 기반 망각)가 명확하다. |
