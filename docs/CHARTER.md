## D1. 정체성

patent-docent = 단일 특허 심층 독해 → 일반 대중용 무료 X 스레드(EN) 엔진.

도슨트 비유: 관람객을 미술사학자로 만들려 하지 않고, 작품 앞의 10분을 만족스럽게 만든다.

자매 프로젝트 = **patent-historian**(복수 특허·전문가·유료). 그쪽은 스크리닝·발굴에서 출발한다.

## D2. 독자상

독자는 학습자가 아니라 **투자자-팬**이다. 독자가 원하는 것:

1. 이해한 것 같은 느낌
2. 그로부터 오는 안도감
3. 남에게 보여주고 싶은 큐레이션 가치

따라서 최적화 대상은 교육의 성공이 아니라 **공유 충동**이다.

(구 PAW의 "학구적 독자" 가정은 실측 반증됨 — 쓰라린 교훈으로 기록한다.)

## D3. 핵심 독트린: "투자자의 질문에, 기술로 답한다"

소재 선정과 훅은 투자자-팬의 불안·질문("해자가 진짜인가, hype인가")에 조응한다.

본문의 답은 특허 물증에 근거한 기술 서사뿐이다 — 예: "HBF는 마케팅 용어가 아니라 실제 준비 중인 기술이다"까지 말하고 멈춘다.

**금지 대상은 어휘가 아니라 화행 3종이다** — ① 독자에게 매매 행동을 권유하는 것 ② 가격·밸류에이션을 전망하는 것 ③ 수익을 약속하는 것.

금융 용어·티커(`$XXX`)·주가·시장 사실의 서술은 **허용**한다 — 훅의 직무다.

기계층은 **화행 플래그** 하나뿐이다: 문장 단위 분류, **거부권 없음**, 체크포인트 2에 첨부한다. 금지 어휘 사전(regex)은 두지 않는다.

투자 결론은 독자가 스스로 내린다.

## D4. 소재

v1은 Owner 지정 특허를 소재로 한다.

안도감이 나올 수 없는 소재는 독해 단계에서 **drop 제안**한다 — 2단으로 낸다: ① 청구항 분해 직후 조기 신호 ② 포지셔닝 확정 후 최종.

"haters 반박형"(방향이 긍정인 디벙킹)은 1급 소재다.

## D5. 독해론 (5단계)

1. **청구항 구성요소 전 분해** — 전 청구항(독립+종속)을 대상으로 한다. 독립항별로 별도 트리를 세우고, 종속항의 부가 한정은 골격 밑 층위로 누적한다.
2. **관계 트리 도식화** — 표 또는 폴더 트리형.
3. **3중 접지** — 구성요소 ↔ 명세서 문단 위치·내용 ↔ 도면부호 대응표.
4. **유기적 통합** — 명세서·도면 근거로 트리들을 연계·합체해 전체 그림을 파악한다.
5. **포지셔닝** — 배경기술·효과 섹션과 대비한 포지셔닝으로 독해를 종료한다.

각 단계는 검증 가능한 중간 산출물을 남긴다. 이것이 "LLM 막연한 추론 1회"의 대체물이다.

**승계 재정 2건**

- **청구항 = 법적 권리범위가 아니라 출원인 관심 신호다.** 독해는 청구항→명세서 참조 방식으로 진행한다.
- **우선일 = 본격 연구개발 개시의 최후 하한선이다.** 서랍-속-정답(gotcha) 독법은 금지한다.

## D6. 주방 분리 아키텍처

```
READ(재료 추출)
  → 재료 명세 (구성요소 트리·접지표·기술적 함의 목록·포지셔닝)
  → ★Owner 체크포인트 1: 재료 승인 (KR 문서)
  → 승인 시 동결 (버전 스탬프)
  → DESIGN (레시피: 훅·논지·트윗 골격·도면 배치)
  → FIGURES
  → COMPOSE (펜)
  → GATE
  → 계기 / 소견
  → ★Owner 체크포인트 2: 변주 선택 + 출하 승인
  → 게시
  → 환류
```

체크포인트 1의 재료 검토가 **Owner 이해층을 겸한다** — 별도 브리핑은 두지 않는다.

**규율 3**

1. **성분 역참조** — 본문의 모든 기술 주장은 재료 항목 ID로 역참조 가능해야 한다. 위반은 게이트 결함이다.
2. **단방향** — 펜은 재료를 수정할 권한이 없다. 재료 결함을 발견하면 READ로 반려하고, 명세를 개정(버전 증가)한 뒤 재요리한다.
3. **결정론의 정직한 위치** — 독해 자체는 LLM 판단을 필요로 한다. 따라서 결정론은 절차 고정 + 산출물 형식 구조화 + 검증 기계화에 산다(트리 항목의 청구항 원문 존재 문자열 검사·접지 포인터 해소 검사·재독해 수렴 검사).

## D7. 게이트 관할권 원칙

**게이트의 관할 = 정답이 존재하는 범위. 한 뼘도 넓게 만들지 않는다.**

정답의 세 서식지:

1. **원천과의 관계** — 재료 대조.
2. **입법된 규칙** — Owner 재정으로 결정론화된 문언(티커·금지 어휘·형식 규격). 기계는 문언만 집행하고, 법의 정신을 외삽하지 않는다.
3. **사후 독자 반응** — 출하 전에는 접근 불가. 환류로만 존재한다.

그 밖의 것은 게이트가 아니라 다음 둘이다:

- **자문** — 플래그·소견. 거부권 없음.
- **결함 카탈로그** — 알려진 나쁨만 차단한다(AI 텔 등). 반증 전용이므로 **통과 ≠ 좋음**. 등재는 Owner 재정으로만 한다.

## D8. 게이트 구조 (3층 + 메타)

펜은 초안을 **주석층**과 함께 쓴다: 트윗·문장마다 근거 재료 ID를 `[M3,M7]`로 표기하고, 근거가 필요 없는 서사 조직은 `[narrative]`로 자기 신고한다. 출하본은 주석을 기계로 제거해 파생한다(게이트 후 무단 수정 봉쇄).

- **L0 결정론 (거부권)** — 스레드 규격·주석층 스키마·인용 ID 해소·**숫자 전수 대조**(본문의 모든 수치·날짜·단위·특허번호가 재료 명세에 포함되어야 함, 화이트리스트 제외).
- **L1 국소 대조 (거부권)** — 문장↔인용 재료 정합, `[narrative]` 신고 감사(기술 주장 밀수 검출). k-반복 다수결로 노이즈를 줄인다.
  - 의미 수준 금지선은 **화행 플래그**다 — D3의 화행 3종을 문장 단위로 분류하고, **거부권 없이** 체크포인트 2에 첨부한다. 판정 적격자는 Owner다.
- **L2 전역 판단 (자문)** — 비평 메모만 낸다. **점수 발행 금지**(굿하트 미끼).
- **메타: 게이트 회귀 스위트** — golden(출하 확정본)과 변조본(환각 주장·권유 문장·무근거 숫자를 심은 판)을 상비한다. 게이트를 수정할 때는 "심은 결함 전부 검출 + golden 전부 통과"를 강제한다.

**루프 위상**

- 결함 → 국소 수정 지시(예: "트윗4 문장2를 M7 내용으로 재서술"), 캡 3회. 수렴 실패는 상류 결함 신호로 보고 Owner에게 에스컬레이션한다(대개 재료 반려행).
- 판단 → 비평 메모 1회 → 펜 자유 리비전 1회로 위상을 봉쇄한다.
- 최종 심급은 이력·메모를 모르는 새 눈이다.
  - **거부권 사유는 셋뿐이다** — (a) L0 전 항목 재실행 실패 (b) 성분 역참조 L1 재검(새 컨텍스트, 같은 k) 실패 (c) 주석층·strip 무결 실패. 그 밖의 발견은 거부권 없이 체크포인트 2에 소견으로 첨부한다.
  - **입력의 경계는 생성 시점이다** — 자격은 **수정 루프 개시 전에 동결된 것**뿐이고(계약 전체·동결 재료 명세·숫자 화이트리스트·반복 횟수 k·슬롯 선언), **수정 루프가 산출한 것은 전부 차단한다**(수정 이력·게이트 로그·점수·비평 메모·계기 데이터·이전 판정). 심판 대상인 최종 초안만이 유일한 예외이며, 제공은 거부권 3종의 임무에서 도출되는 최소 목록으로 한정한다.

게이트는 **어떤 경우에도 직접 글을 고치지 않는다**(검사자 소견 / 펜 집필의 관할선).

**펜 프롬프트에 금지 목록 금지** — 긍정형(스코프 선언 + 도슨트 정체성)만 담는다. 금지 열거는 검증 심급에만 둔다("코끼리를 생각하지 마" 프라이밍 방지).

## D9. 자문 3역 (계기·소견·재정)

**계기 = Haiku n대.** 자기보고는 금지한다(LLM 내성 불신) — 행동 프로브만 쓴다: 스레드만 읽고 ① 핵심 주장 3문장 재서술 ② 재료 명세에서 파생한 표적 질문에 답변.

- **채점은 Haiku가 하지 않는다.** 별도 채점자가 동결된 재료 명세를 정답지로 삼아 대조한다(핵심 사실은 결정론 대조).
- 걸림 위치는 채점 결과 + 주석층 역참조로 국소화한다(전달에 실패한 재료 → 해당 트윗 자동 지목).
- **계기 교정**: golden/변조 표본에서 판별력(golden 높고 변조 낮음)을 확인한다 — 회귀 스위트 인프라를 공용한다.
- **측정 대상 = 전달 충실도**("막힘 없이 읽히는가" — 새 독자상 기준). 진짜 이해 퀴즈가 아니다.

**소견 = Fable.** 비평 메모를 쓴다(훅 조응·안도감 착지·도슨트 보이스; 계기 데이터를 반영).

**재정 = Owner.** 구속력 있는 결정은 이 단계뿐이다(변주 선택·출하 승인).

## D10. 펜 토너먼트

변주 2~3판을 **이종 펜**(서로 다른 펜 레인)에 배정한다 — 같은 재료·같은 블루프린트 = 공정 비교. 변주 간 차이는 한 축뿐이다.

- **1호 런 = Opus 5 단일 벤더 effort 사다리 3판(high / xhigh / max).** 이 런에서 펜을 가르는 축은 effort다.
- **2호 런부터 = 1호의 effort 승자 티어 + 교차벤더 편입.** 교차벤더는 GPT-5.6-sol 단일이다.

Owner의 선택 1회는 **모델 토너먼트 표**와 **취향 데이터**(보이스 앵커·결함 카탈로그 사료)에 이중 기입된다. 토너먼트 표는 **effort 비교와 모델 비교를 별개 축으로 구분 기록**한다.

배치 단위 승률이 70% 이상으로 굳으면 주전 승격 + 변주 수 축소.

## D11. 형식

- ① **채널** — X 스레드, EN. 장문 포스트는 쓰지 않는다(피드 물리).
- ② **형식의 단위는 전시물이다** — 한 트윗 = 한 전시 스톱(도면 중심)이며, 트윗 수는 전시물 수의 종속변수다.
- ③ **스레드는 슬롯 아크를 따른다** — 훅 → 전시 스톱들(반전 포함) → 착지 → 꼬리. 슬롯의 역할: 훅 = 투자자의 질문 + 최강 도면(스레드의 성패 그 자체) · 전시 스톱 = 전시물 하나의 제시 · 반전 스톱 = 질문에 답하는 결정적 물증 · 착지 = 안도감 결론(인용·스크린샷의 표적) · 꼬리 = 링크·팔로우.
- ④ **형식의 모든 수치는 헌장이 아니라 형식 파라미터 시트가 관할한다** — 정본 = `contracts/format-parameters.yaml`. 시트는 배치 리뷰의 재정으로 교정되며, 그 교정에 헌장 개정은 필요하지 않다.

## D12. 도면 = 핵심 자산

근거: "독자는 글보다 이미지부터 본다"(Owner 실관찰).

- **전량 선편집 + 자산층 보존 + 출하 선택은 포인터만.** (구 v3 C17 교훈 승계 — 선택분만 편집하면 재편집 왕복과 유실 위험이 생긴다.)
- **렌더 스택 = HTML/CSS/SVG 조판 → 헤드리스 Chromium → PNG 1200×675 @2x**(16:9 피드 안전 크롭). **matplotlib 금지**(미감 천장 실증 — 구 차트 산출물 만족도 저조).
- **사용권 재정.** 특허 도면 2차 편집물의 공개 게시 여부는 **첫 출하 전 Owner 재정 1회**로 정한다(실물 시안을 보고 판단). 그전까지 자산 생성·내부 검토는 진행하되 **게시는 보류**한다.
- **잠정 편집 규칙.** 특허 도면 원본의 사용은 **크롭만** 허용한다. 주석 오버레이·재조판은 보류하며 첫 출하 전 재정 대상이다.
- **자체 제작물**(재료 명세 기반 개념 다이어그램·수치 카드)은 원본을 포함하지 않으므로 이 제약 밖이다.
- **템플릿 스튜디오**(부트스트랩 후 별도 발주): **자작물 템플릿 중심**(개념 다이어그램·수치 카드) + 도면은 **크롭 프레이밍만**. 템플릿별 시안 3안 + **폴백(원본 크롭 + 최소 주석) 상비**. 주석·재조판 템플릿 시안은 **내부 검토용으로만** 제작하며, 사용 여부는 사용권 재정에 묶인다. 같은 재료로 변인을 통제하고, 실물 게시 규격 PNG로 제시하며, Owner 선택 1~2라운드 후 디자인 토큰 + CSS를 동결한다("디자인은 한 번, 생산은 기계").
- **폴백 상비 = 정직성 장치.** 폴백이 연승하면 시각 정체성 폐기를 데이터로 재정한다.
- 다크 + 앰버(#171A21 / #D19730)는 후보 팔레트 중 하나일 뿐이다(확정 아님).
- 선택·기각과 그 이유는 교정 원장에 기록한다.

## D13. 환류 — 두 장부와 지표 규율

지표는 원시 전량을 추가 전용 원장에 저장한다(항목·72h 스냅샷·맥락 포함). 절대 성과 보고는 원시를 쓴다. 앵커 가중·fade는 반복 패턴 근거의 제안만 허용하며 확정은 배치 리뷰의 Owner 재정 전용이다(단일 글 근거 제안 금지·자동 확정 금지·10건 미만 전원 잔류). 자동 정규화는 도입하지 않으며, 시대 드리프트 실측 시 재정으로 도입한다. 환류는 재정을 거쳐서만 생성계(앵커·카탈로그)에 도달하고, 지표는 게이트가 아니다. 회귀 원장(게이트·계기 검증 표본)은 독자 반응과 무관하게 재정으로만 큐레이션한다.

- **계기 유효성 점검**: 배치 단위로 계기 점수 ↔ 실반응의 상관을 확인한다. 무상관이면 프로브를 재설계한다.
- **v1 지표 수집 = 수동 입력**(72h 시점, 런당 1~2분). X API 자동화는 추후.

## D14. historian 인터페이스

**재료 명세 스키마 = 두 프로젝트 간 계약이다.** historian은 "재료 명세 N개를 모아 교차 분석"으로 정의된다.

독해층 이식 방식:

- 스냅샷 + `PORTED-FROM.md`(원천 커밋 핀)
- **`reader-version` 상호 체크** — 독해층을 수정하거나 주로 사용하는 작업을 할 때 상대 리포의 reader-version을 확인한다. 어긋남을 발견하면 **자동 동기화 금지·Owner 상신**한다. 이 규율은 리포 CLAUDE.md에 명문화한다.

X Article(장문)은 historian 채널 후보로 기록해 둔다.
