[**ⓐ 감시 범위의 정직한 한정.** `functools.partial(read_stage.run, shadow_root=None)`에서 감시 함수는 `Call.func`가 아니라 인자에 있으므로 현재 관문 대상이 아니다. 이를 동적 전달·함수 참조의 도피라는 ‘안 보는 축’에 명기하는 것은 정직하다. 다만 그 경우 보증은 특정 구문의 회귀 검출이지, 원래 목표인 ‘어떤 시험도 생산 원장에 쓰지 않는다’ 전체가 아니다. A-01은 이러한 범위 밖 사례가 아니라 **현재 직접 호출 판정 내부의 반례**다. ]

[**ⓑ 동적 강제의 타당성과 한계.** 정적 검사와 동적 쓰기 차단을 병행할 논거는 충분하지만, 그것이 곧 엔진에 pytest 인식 분기를 넣어야 한다는 결론은 아니다. 제안된 환경변수와 Boolean `ContextVar`만으로도 부족하다. 보호 중 복사한 `contextvars.copy_context()`는 부모가 값을 재설정한 뒤에도 참을 유지하는 것을 축약 재현에서 확인했다. 표지가 필요하다면 실제 대상에 결속되고 종료 시 철회되는 허가 객체여야 하며, 최종 쓰기 지점에서 검사해야 한다. 엔진 값 공간 변경은 재정 대상으로 남는다.]

[**ⓒ 보통의 링크된 worktree 자체는 새 반례가 아니다.** git 조회가 정상이고 공용 git 디렉터리가 실제 주 트리의 `.git`이면, 임시 위치의 worktree라도 `_main_worktree_by_git`가 임시 범위 밖 주 트리를 반환하므로 ②에서 거부된다. 가짜 리포를 사용한 재현에서도 그렇게 동작했다. `bare.git` 배치의 헬퍼 폴백과 엔진의 루트 거부 역시 첨부 코드와 정합한다. 핵심 구멍은 링크된 worktree 일반이 아니라 **검증 대상과 호출 대상의 불일치, 원장 하위 경로의 링크, 검사 뒤의 상태 변화**다.]

[**ⓔ 허가 범위.** 첨부된 `source.run` API와 T40·T4 문언 기준으로, `partial_until` 필드명·필수화, 비partial의 비null 값 거부, `lane_dir`의 정규식 재검, 기존 `CheckRow`에 경로 거부 finding을 넣는 것은 공학 집행으로 판정한다. 특히 비partial 거부는 기존 API가 받지 않던 **새 필드의 적용 범위**를 정하는 것이므로, 그 자체를 종전 허용 입력을 축소하는 추가 입법으로 볼 근거는 부족하다. `terminates_at_enum` 13종도 기존 SPEC의 종료 스테이지 집합을 그대로 옮긴 것이라면 같은 판정이다. 다만 13종의 SPEC 원문 대조는 이번 봉투에서 독립 확인하지 못했고, 이전 감수문이 일치를 보고한다. 승격 정책을 제거한 v3에서 이 다섯 변경을 다시 입법으로 지적할 충분한 근거는 찾지 못했다.]

[**ⓕ 이미 정합해진 부분과 남는 보증 범위.** `_engine_pin` 직후·승계 확인 및 입력 읽기 전이라는 가드 위치는 첨부 `source.run`과 정합한다. `fullmatch`도 끝 개행을 거부한다. FileLaneAdapter 실왕복의 비null 요청 지문을 사용하고 기록본을 재독하는 로그 대조는 구판의 `digest-file-missing`과 새 경로 거부를 구별하는 유효한 설계다. 그러나 판정·사유 토큰만으로 ‘루트 밖 파일을 읽기 전에 거부했다’까지 증명되지는 않는다. 또한 `partial_until`의 기록·어휘 검사는 실제 종료선 초과 실행이나 비게시 정책의 강제와 별개이며, v3 반경에는 그 강제의 증명이 없다.]

[**ⓖ 가드 부재 기준판.** 정당한 차별 대조다. 다만 증명하는 것은 **새 API에서 해당 가드가 거부를 일으킨다**는 것이지, 구 릴리즈가 그 새 인자를 잘못 처리했다는 사실은 아니다. 더 명확한 형태는 완성본을 기준으로 서명·계약·배관·시험 입력을 고정하고, 대상 가드만 최소 변조로 제거했다가 복원하는 것이다. 기준 해시와 제거 diff, 정상 입력 대조군, 거부 대상이 실제 기록까지 도달한 출력을 함께 남기면 `TypeError`·준비 실패와의 혼동 및 중간 상태의 재현 불확실성이 줄어든다.]

[**ⓓ 추가 감사 경계.** `_write_shadow_pointer`의 ‘도달 불능’은 **루트 환경이 유지되는 정상 `run()` 경로**라는 조건 아래에서만 인정할 수 있다. 같은 인자라고 해서 두 해석 시점의 파일시스템·git 상태까지 같다는 뜻은 아니다. 경로 검사와 실제 I/O 사이의 교체 문제도 별도로 남으며, 이번 축약 재현은 동시 변경까지 봉쇄했음을 증명하지 않는다.]
