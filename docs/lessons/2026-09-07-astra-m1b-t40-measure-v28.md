**NZ-1 · HIGH · ⑴ P5 위반 — 지표기의 `git status`가 원본 Git 인덱스에 쓸 수 있다.**

좌표: 메모 §5′.3·§5′.5 P5; [t40_metrics.py:356](/home/laptop/projects/workspaces/pd-m1b-t40/bundle/t40_metrics.py:356).

실제 호출은 다음과 같다.

```python
subprocess.run(
    ["git", "-C", run_repo, "status", "--porcelain", "--",
     "contracts", "engine", "reader"],
    capture_output=True, text=True
)
```

`--no-optional-locks`도, 이를 보장하는 환경 설정도 없다. 설치된 `git-status(1)`의 **BACKGROUND REFRESH** 절은 기본 `status`가 stat 정보를 갱신하고 인덱스를 기록한다고 명시한다. 링크된 worktree의 인덱스는 **원본 주 작업 트리의 Git 관리 디렉터리**에 있으므로 sandbox 밖이다.

메모리 대역에서도 위 인자와 `env=None`을 확인했다. 실제 인덱스 갱신은 실행하지 않았다.

끊긴 연결은 **“Python 쓰기 호출 없음 → 지표기 부작용 없음”**이다. 하위 프로세스의 쓰기가 빠졌으며, 부적격 판정 전에 발생할 수도 있다.

**수정 문안:** “원본 리포를 조회하는 Git 호출에는 `--no-optional-locks`를 적용하고, P5 쓰기 목록에 하위 프로세스의 Git 관리 파일까지 포함한다.”

**NZ-2 · HIGH · ⑴ P6 위반 — T43 판별이 산출물 정합 검사와 재실행 성공에 종속된다.**

좌표: 메모 §5′.4·§5′.5 P6·§5′.8; [t40_metrics.py:573](/home/laptop/projects/workspaces/pd-m1b-t40/bundle/t40_metrics.py:573), [t40_replay.py:219](/home/laptop/projects/workspaces/pd-m1b-t40/bundle/t40_replay.py:219).

메모는 **“P6은 P2 재실행에 앞서 판별한다”**고 적었지만 실제 순서는 다르다.

- 지표기는 영수증을 읽기 전에 포인터·판정서·lane-log를 파싱한다.
- 대조기는 sandbox 생성과 호출 전 대조를 마친 뒤, **각 호출 루프 안에서** IO 결함을 판별한다.
- 따라서 뒤 호출에 결함이 있으면 앞 호출들은 먼저 재실행한다.

실제 `write_json`에 메모리 파일 객체를 제공하여 `[`까지 기록한 뒤 `OSError`가 나는 경우를 만들었다. 이 바이트를 lane-log로 제공하고 IO 영수증 조회를 관측했다.

```text
PARTIAL_WRITE artifact=b'[' io_fault=True
FAULT_METRICS exit=4 receipt_reads=0 replay_calls=0
last=[t40_metrics] lane-log JSON 판독 실패: JSONDecodeError(...)
```

별도로 실제 `replay()` 본문에 정상 호출→IO 결함 호출을 공급했다.

```text
P6_ORDER replayed=1 runner_calls=1
```

첫 결과는 **재실측 처분 누락**, 둘째는 §5′.8의 선후관계 반증이다. 검수 환경에서 앞 호출 재현이 실패하면 이미 기록된 뒤 호출의 IO 결함까지 도달하지 못한다. “IO 문언 생성 자리가 둘뿐”이라는 사실은 **그 두 자리가 반드시 실행됨**을 증명하지 않는다.

**수정 문안:** “런 식별·영수증 형식과 결속을 확인한 직후 전체 호출의 T43 근거를 먼저 판별하며, 해당 런에는 산출물 정합·중간 상태 재현을 재실측 처분의 선행조건으로 걸지 않는다.”

**NZ-3 · MED · ⑴ P7 위반 — 부적격과 검수 불능의 처분이 코드에서 보존되지 않는다.**

지표기는 IO 결함 문언 이외의 반환을 모두 다음 문언으로 감싼다.

