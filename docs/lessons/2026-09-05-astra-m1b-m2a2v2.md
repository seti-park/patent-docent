원장만 손상시키는 대안에서는 ⓐ의 `terminated:true` 포인터가 그대로다. 정상 구현은 ⑴에서 종결을 확정하므로 **「종결한 런 재호출」**로 실패한다. 요구된 **「종결 판정 불가」**가 아니다. 포인터만 지워도 ⑵의 full 판정서가 남는다.

고치는 문안 한 줄: **“ⓘ를 근거별 독립 사례로 나누고, 원장 손상 사례는 포인터·최종 판정서를 제거한 뒤 손상행 앞·뒤의 동일 ID 행 배치를 검사하여 `종결 판정 불가`와 바이트 불변을 단언한다.”**

**MK-3 · MED — MJ-1의 원장 행 형태 분기가 아직 완결되지 않았다**

좌표: [발주문 §1①](/home/laptop/projects/workspaces/pd-m1b-m2a2/bundle/SPEC-round-m2a2.md:12), [처분 §34](/home/laptop/projects/workspaces/pd-m1b-m2a2/docs/decisions/D-20260903-04-t31-t32.md:1516).

v2는 포인터·판정서의 객체 여부와 필드 자료형을 열거했지만, 원장에는 **“JSONL 손상행(한 줄이라도 파싱 불가)”**만 구체화했다. 읽기 전용 JSON 파싱 실출력:

```text
null             → NoneType
[]               → list
42               → int
{}               → dict
{"run_id":null}   → dict
```

모두 파싱에 성공한다. 원장 행이 비객체이거나 `run_id`가 없거나 잘못된 자료형일 때, 이를 형태 위반으로 거부할지 “그 run_id 없음”으로 처리할지 분기 목록에서 확정되지 않았다. `.get()`을 바로 쓰면 `AttributeError`, 비객체를 건너뛰면 비종결 통과라는 서로 다른 구현이 나온다.

또한 “근거 부재만 거짓”은 유효한 `terminated:false`도 다음 근거로 진행한다는 §1③과 함께 읽어야 뜻이 완성된다. 부재·유효한 비참·판정 불가를 명시적으로 나누는 편이 정확하다.

검증 경로: ⑴⑵ 부재 → 위 원장 행 → 형식 검사·건너뛰기·직접 필드 접근 중 어느 구현을 택하느냐에 따라 처분이 갈린다. **MH-4/MJ-1의 형태 경계 공백이 일부 남았다.**

고치는 문안 한 줄: **“원장 행의 비객체·`run_id` 누락/자료형 위반은 판정 불가 `StageError`로, 유효한 false 포인터·비full 판정서·다른 ID 행은 다음 근거로 진행하도록 읽기 검증 분기를 명시한다.”**
