# T28 — `read.convergence` 는 출구에서 재시도하지 않는다 (재정 P-4 의 이행 · T26 §3 ② 의 명시 예외)

## §1 무엇이 문제였나 (sol 도전 B-1 · 상류 = 재정 P-4)

재정 P-4(2026-08-18 · `ruling-20260818-03-P1-P11.md`)는 수렴 검사의 `retry(1)→escalate` 경로를
**조기 지점으로 옮겼다**(원문 *「retry(1)→escalate 경로를 조기 지점으로 이동」*). 계약도 그렇게
적혀 있다 — `contracts/stages/read.yaml` 의 convergence exact-match 행은 `points: [early]` 이고
note 가 *「접지 지출 이후로 미루지 않는다(재정 P-4)」* 다. 그런데 **오늘의 러너는 출구 실패를
종류 불문 재시도한다**(`retry_budget` 출구 판정점의 `checks: checks_before_exit` 에
`read.convergence` 가 들어 있다) — 조기에 통과한 수렴이 출구 재검사에서 갈리면 꼬리 레인을 한
번 더 돌린다. 계약이 `[early]` 만 신고한 행을 출구에서도 재시도하는 **P-4 위반 실물**이다.

T26 ⒜ ③ 이 판정점별 재시도 목록을 명시적으로 적게 만들면 이 자리를 어느 쪽으로든 결정해야
한다. 설계 v1 은 원장(P-4)과 계약 행을 따라 출구 목록에서 convergence 를 뺐고, 도전자는 그것이
T26 §3 ② *「오늘의 판정표 불변」* 과 충돌한다(오늘의 행동이 바뀐다)고 지적했다 — **원장 두
조항(P-4 · T26 §3 ②)이 이 한 자리에서 서로 어긋난다.** 그 해소는 재정이다.

## §2 T28 — 채택 (β)

### ⒜ 결정

| 항목 | 값 |
|---|---|
| 계약 행 | convergence exact-match 행은 **`points: [early]` 그대로**. `[early, exit]` 로 넓히지 않는다 |
| 출구 재시도 목록 | `read.convergence` 를 **제외**한다(T26 ⒜ ③ 의 명시 목록에서) |
| 출구 convergence 실패 | 재디스패치 없이 **즉시 `escalate`** — 조치 `escalate`, 라벨은 오늘과 같은 exact-match 축 행의 것 |
| P-4 | **유지**. 개정하지 않는다 |
| T26 §3 ② | **명시 예외 추기**(아래 ⒟) |

### ⒝ 사유 (상신 원문의 셋)

⑴ Owner 가 이미 P-4 로 정했고 계약·SPEC 이 그렇게 적혀 있다. 지켜지지 않은 것은 코드다 —
**코드를 원장에 맞추는 쪽**이 원장을 코드에 맞추는 쪽보다 이 리포의 규율(원장이 상류)에 맞는다.
⑵ 출구 convergence 실패는 실런 3건에 전례가 없고, 이론상 「조기 통과 → 출구 실패」는 정본 실행
하나만 남은 뒤라 peer 와의 비교 자체가 조기 값의 재사용이다 — 재시도로 달라질 것이 없다. 조기
통과 뒤 출구에서 깨진 수렴은 **비정상 신호**이고 P-4 의 취지(접지 지출 뒤에 재시도 비용을 더 쓰지
않는다)가 정확히 이 자리를 겨눴다. 사람이 봐야 한다. ⑶ α 는 P-4 개정이라 재정 문언을 고치는
일이고 β 는 예외 표기다 — 비용이 작다.

### ⒞ 기각 — α (출구 재시도 허용)

계약 행을 `points: [early, exit]` 로 넓히고 P-4 를 *「조기 지점으로 이동」→「조기 지점 추가」* 로
개정하는 안. 오늘의 행동은 불변이지만 **원장 개정으로 코드를 추인**하는 형태이고, 그 논리(꼬리
레인이 명세를 바꿨다면 재시도가 고칠 수 있다)는 P-4 가 이미 기각한 가정이다.

### ⒟ T26 §3 ② 의 명시 예외 (원장 규율 3 — 추기)

T26 §3 ② 는 이 파일이 **추기**로 좁힌다. 문언(상신 원문 그대로):

> *「T26 골든에서 `read.convergence` 가 출구 실패 집합에 든 칸의 재시도 여부는 P-4 의 이행이며
> 회귀가 아니다 — (조치, 라벨) 은 불변이고 재시도 횟수만 0 이 된다」*

**★ 총괄 정밀화 — 「불변」이 무엇을 가리키는지를 실물에 맞춰 적는다.** 오늘의 표는
`_failure_verdict`(`engine/stages/read.py`)가 정하는 함수 **(출구 실패 집합, repeated) → (조치,
라벨)** 이다. β 는 이 함수의 **값을 한 칸도 바꾸지 않는다** — convergence 가 든 집합은
`repeated=False` 면 오늘도 내일도 exact-match 축 행(`escalate`)이고, `repeated=True` 면 오늘도
내일도 「같은 실패 서명」 행이다. β 가 바꾸는 것은 러너의 **재시도 결정**(어느 칸에 도달하는가)
하나다: convergence 가 든 출구 실패 집합은 재디스패치 없이 바로 자기 칸으로 간다(1회 → 0회).
그 결과 **`repeated=True ∧ convergence ∈ 집합` 인 칸은 출구 경로에서 도달 불능**이 된다 —
값은 그대로 두고 골든에 「경로상 도달 불능」 표지만 단다. 상신 원문의 **「예외 1칸」은 골든의
칸 하나가 아니라 예외 표기 한 건**(convergence 가 든 출구 집합 전체에 대한 재시도 규칙 한 줄)을
뜻한다 — 그 집합은 2¹¹ 개이므로 「칸 하나」로 읽으면 틀린다.

### ⒠ 성질

규율 11 의 정규 선상신. **원장 두 조항의 충돌 해소**이며 P-4 의 값(재시도 자리 = 조기)을
지킨다. T26 §3 ② 는 개정이 아니라 예외 추기다(원장 규율 3 — 후속 변경은 추기·새 파일).

원장 T26 ⒜ ① *「행에 검사 id 를 키로 단다 — 각 행에 `checks: [...]` 명시 키」*. 실패표에는
검사 실패가 아닌 행이 셋 있다 — 「같은 실패 서명 재현」(반복) · `gate-escalation`(조기 국면
게이트 상신) · `upstream-defect`(하류 반려 수신 · 호출자 없음 · T2 PD-M5 이연). 이 셋에
`checks` 를 달 수 없다(검사가 아니다). 설계 v1 은 셋을 `kind` 예외로 두었고 도전자는 그것이
**원장 문언을 조용히 좁혔다**고 지적했다 — *「`kind` 라는 키 자체는 공학적 해법이 될 수 있다」*
고 하면서 요구한 것은 **명시**였다.

## §2 T30 — 채택 (ⓐ)

### ⒜ 결정

| 항목 | 값 |
|---|---|
| `checks:` | **검사 실패 행에만.** 원장 T26 ⒜ ① 의 「각 행」은 「검사 실패 행 각각」으로 읽는다 |
| 검사가 아닌 세 행 | `kind: <식별자>` — 사전 3종 `retry-repeat`(같은 실패 서명 재현) · `gate-escalation` · `upstream-defect`, **각 정확히 1행** |
| 관문 ⒜(선언 검사 전체 ↔ `checks` 합집합) | **`checks` 행만** 대조. `kind` 행은 「검사 없는 행」 심기(관문이 잡아야 하는 결함)와 **구별**된다 — 한 행은 `checks` 와 `kind` 중 **정확히 하나**를 가진다(둘 다·둘 다 없음 = 관문 실패) |
| `upstream-defect` 행 | **식별 키만.** 수신 코드를 만들지 않는다(T2 — PD-M5 이연). binding 분류 `deferred/test_bound` |

### ⒝ 사유

`checks: []` 나 가상 id 는 관문 ⒜ 가 잡아야 하는 「검사 없는 행」 심기와 구별이 안 된다 —
관문 설계가 자기모순이 된다. `kind` 는 「이 행은 검사 실패가 아니라 다른 사건의 처분이다」를
**키 이름으로** 선언하므로 관문이 두 부류를 기계로 가른다. 도전자의 요구는 해법의 교체가 아니라
**해석의 명시**였고 이 재정이 그것이다.

### ⒞ 기각 — ⓑ (세 행도 `checks` — 빈 목록 또는 가상 id)

문자 그대로 읽는 안. 관문 약화(위) · 가상 id 는 선언 검사 목록에 없어 관문 ⒜ 의 차집합 0 을
깨거나, 깨지 않으려면 관문에 예외 목록을 두어야 한다 — 예외 목록이 곧 `kind` 사전이다.

### ⒟ 성질

규율 11 의 정규 선상신. **원장 문언의 해석 확정**(값 공간 무변경). 원장 T26 ⒜ ① 의 문언은
고치지 않고 이 파일이 해석을 든다(원장 규율 3).
