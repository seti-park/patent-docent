## §3 처분 대기 2건의 처분 — `S-1` · `S-2`

`DISPOSITIONS.md` §2 에 서 있던 두 줄이다. id 는 총괄이 세웠고(원문에 없다 · 사후 확인 대상), 처분은 아래대로다.

### S-1 — 레인이 정본 트리에서 `git apply -R` 로 역프로브를 도는 방식(`opus-audit-t17-repair` §6 소견 ⑴)

**처분 = 수용.** 감수자의 권고 문언은 *「프로브 레인에 정본 트리 쓰기 권한을 주지 않는다 — `git worktree add` 또는
`git clone --no-hardlinks` 로 별도 트리를 받고 거기서만 패치·되돌림을 한다」* 이고, 그 근거는 감수자 자신이 적었다 —
이것은 SPEC §8.3 9항 ⓐ 가 **감수 레인**에 이미 요구하는 규격(재정 S5 · Q9 ⓐ)이며 *「검사자에게 쓰기를 주면 격리
사본에서만」* 이라는 논리는 역프로브에도 그대로 적용된다.

**무엇이 바뀌나.** 규격 자체는 새로 만들지 않는다 — 있는 규격의 **적용 범위를 저작 레인의 역프로브까지** 발주문이 명시한다.
발주문 골격(`D-20260902-02` §5 ⑹⑺⑻)에 **⑼** 를 더한다:

> ⑼ **역프로브·변조 반증·되돌림이 있는 발주는 발주자가 만든 격리 사본(worktree 또는 `--no-hardlinks` 클론)에서만
> 돈다. 레인에 정본 트리 쓰기 권한을 주지 않는다.** 감수 레인의 규격(SPEC §8.3 9항 ⓐ)이 저작 레인의 역프로브에도
> 같은 이유로 적용된다 — 되돌림 실패가 정본에 닿을 경로 자체를 없앤다.

**이미 그렇게 하고 있었는가 — 확인된 것만 적는다.** 라운드 C 저작(opus-coder)은 worktree `round-c` 에서 돌았다(`git worktree
list` 에 아직 있다). 라운드 A 감사(opus max)는 격리 클론 `/tmp/audit-round-a-x9` 에서만 돌았다(감수 원문 `2026-09-02-opus-
audit-round-a.md` :15·:36 — 정본 트리 지문 전후 동일). **라운드 A·A′ 저작 레인(sol-coder)의 실행 트리는 이 문서가 확인하지
못했다** — worktree 가 남아 있지 않고 D-01 이 그것을 적지 않았다. 사건이 난 것은 T17 수리 라운드(`39286ca`)의 저작 레인이며,
그 뒤의 발주가 격리를 지켰는지가 **기록으로 남지 않는다는 것 자체**가 골격 ⑼ 가 필요한 이유다 — 발주문에 적히면 레인 보고에
남고, 남으면 대조할 수 있다.

**왜 값 공간이 아닌가.** 검사·게이트의 판정 공간을 건드리지 않는다 — 레인의 실행 환경 규약이다(규율 11 ③ 공학 집행).

### S-2 — 규율 10 의 판별선은 「파일」이 아니라 「저자·절」(`opus-audit-t17-repair` §6 소견 ⑵)

**처분 = 수용 — 이미 집행되었다.** 재정 2026-09-01 **T20**(`ruling-20260901-09-T18-T20.md`)이 규율 10 을 개정하고
다섯째 관문 `check_lesson_authorship.py` 를 세웠다. 이 자리에 비어 있던 것은 처분이 아니라 **id** 였다.

**Q4·Q5·Q7 의 판정을 그대로 받는다** — 총괄 재량 넷 「적정」, 레인 이탈 3건 「정당」, 후속 커밋 2건 「정합」. 이것은 감사자의 채점이고 총괄 자기 감사가
아니다(ROUTING ⑸ 「발주자 자기 감사는 증거가 아니다」의 반대편).
