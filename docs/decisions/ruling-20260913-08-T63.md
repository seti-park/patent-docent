## ② 선두 「wherein」 경계 = **A′ · 규약 ① 확장 — 「wherein」 한 낱말만**

> 경계 규약 ①: 선두 등위접속사(`and`·`or`)와 **선두 `wherein`**, 그리고 그 뒤 공백은 element·addition 의 `text_verbatim` 에 포함하지 않는다. **`wherein` 한 낱말만이다** — 「특허 용어의 특수성을 고려해서」(Owner). 다른 연결어(`further comprising` · `such that` · `whereby` 등)로 **유추 확장하지 않는다**.

**총괄 해석(원문이 아니다)** — A′ 의 「wherein만」은 총괄 초안 A 의 낱말 목록(`and · or · wherein · and wherein`)에서 **낱말 목록을 `wherein` 하나로 좁힌 것**으로 읽는다. `and wherein …` 은 ①의 `and` 처리 뒤 `wherein` 처리가 **순차 적용**되어 같은 결과가 나므로 별도 항목이 필요 없다(확장이 아니라 귀결). element·addition 공통 적용은 A 그대로. 이 해석이 Owner 뜻과 다르면 정정 재정으로 고친다.

**근거(실측 · 런 -2)** — 두 분해의 element 집합 차이는 정확히 한 원소 = CL-1/e2/e1 의 선두 「wherein 」 유무(read-a 포함 · read-b 제외 · 공통 5/6 → Jaccard 0.714 → 상신 T61). 규약 ①(2026-08-18 · and·or)이 생긴 계기와 같은 꼴. 세 런 축 값 = element-set 1.0 / 0.714 / 1.0 · tree-edges 0.091 / 0.714 / 1.0. 입법 자리 = `reader/procedure/10-decompose.md` 경계 규약 ① + addition 절에 「①·③·④ 는 addition 에도 적용」 명시. 기각 = B 비교기 정규화(검사기가 「무엇을 같다고 볼지」를 정하기 시작 · 코드·시험) · C 유지(낱말 하나에 Owner 한 판).
