## §1 경위 (총괄)

- **⑴ `screening_memos[].read_run`** — T32(2026-09-02)가 `canonical_selection.read_run` 을 `$defs.read_run` 에 묶으면서 총괄이 같은 값 공간의 둘째 자유 문자열을 발견해 상신(원장 T28-T32 §5 ②). 규율 11 상 값 공간 축소라 총괄이 넓혀 집행하지 않고 §3 에 동결. 선택지 = ⓐ 같은 `$defs` 참조로 묶는다(총괄 추천 · 단일 진원 완성 · 없는 실행 id·역할 접미·오타를 기계가 거부 · 실런 3건 값 전부 `read-a`·`read-b` 라 영향 0 · 행위시법 P-U1 · 단점 = 장래 새 실행 id 는 스키마 개정이 재정 사항) / ⓑ 자유 문자열 유지(같은 개념에 두 타입 잔존).
- **⑵ `reported_by` `maxItems: 2`** — 라운드 RD 좁은 재감사(opus max · `docs/lessons/2026-09-05-opus-audit-round-rd.md` Q5 「새로 드러난 것」 ⒞)가 짚음: 길이 상한 2 가 `items.enum` 크기 2 + `uniqueItems` 의 우연한 곱으로만 서고 `maxItems` 선언이 없다 — enum 에 셋째 값이 들어오는 날 상한이 소리 없이 3 이 된다. 감사자가 「값 공간 축소이므로 재정 사항 · 총괄이 조용히 넣지 말 것」이라 적었고 총괄이 §3 에 상신(`D-20260903-04` §12). 선택지 = ⓐ 넣는다(총괄 추천 · 「두 독해 실행」 설계 의도를 스키마가 직접 말함 · 오늘 값 공간 불변 · 실런 영향 0) / ⓑ 넣지 않는다(오늘 차이 없음 · 셋째 실행이 생기는 날 함께 정함).
- **⑴⑵ 는 같은 파일(`contracts/schemas/convergence.schema.json`)의 read_run 값 공간**이라 한 재정으로 묶어 올렸다.

- **⑷ 사후 확인 ⓖ~ⓠ** — 규율 11 재량 집행분 열한 건(`HANDOFF-NEXT.md` §0 14차~16차 · 결정 자료 페이지 6절에 「제가 한 판단 / 되돌리면」 표).

## §4 효력 (총괄)

- T35 는 **값 공간 축소**다 — 새 규격은 다음 런부터(행위시법 P-U1 · `runs/**` 기존 산출물 무소급 · T32 와 동일). 오늘 실런 3건은 두 자리 모두 새 규격을 이미 만족한다(`read-a`·`read-b` · 길이 ≤ 2).
- T36 ⑷ 추인은 효력을 확정할 뿐 절차를 소급해 만들지 않는다(재정 S2). ⓘ·ⓞ·ⓠ 의 「총괄 실수·유실·간섭」 기록은 그대로 남는다.
- **T32 §3 ①의 「참조 둘」은 T35 ⑴ 로 「참조 셋」이 된다.** T32 원장은 고치지 않는다 — 후속 개정은 이 파일이 든다(닫힌 것도 어떻게 닫혔는지 남긴다).
- `RULINGS-LEDGER.md` §3 의 두 미결 행은 지우지 않고 **이 파일을 가리키는 포인터**로 바꾼다(상신 당시 문안 보존).
