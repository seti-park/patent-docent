## §3 정정 — 「다음 = 예행 런」은 낡은 문장이다

`CLAUDE.md` §6 과 총괄 메모리가 다음 좌표를 *"로드맵 상신 → 예행 런"* 으로 적어 왔다. **뒤엣것이
틀렸다.**

SPEC §8.2 가 정의한 예행 런은 이렇다 — 재정 P-9 원문:

> 예행 런 = **strip 산출까지 완전 리허설**(CP2 변주 선택 포함, 게시만 제외).

그리고 같은 절이 못 박는다: *"「예행이니 여기까지」로 임의 단축한 것은 통주가 아니라 부분 시험이다."*

종료선 `50-gate/<variant>/thread.stripped.md` 에 도달하려면 파이프라인 전경(§1.1)의 경로상
**design → figures → compose → gate** 넷을 지나야 한다. 대응 모듈은 넷이다.

| 필요 모듈 | 무엇을 지어야 예행이 가능한가 | 현 상태 |
|---|---|---|
| **PD-M3** | 주석층 문법 파서 + strip(정·역방향 무손실) — `thread.stripped.md` 를 만드는 코드 | 디렉터리 없음 |
| **PD-M9** | FIGURES 폴백 경로 — 주석 태그 `{fig: fig-03}` 이 가리킬 대상 | 없음 |
| **PD-M5** | DESIGN 블루프린트 + COMPOSE 펜 레인 — 변주가 없으면 CP2 변주 **선택**이 성립하지 않는다 | 없음 |
| **PD-M4** | `gate` 스테이지 러너 + L0 — 예행 제약표가 *"거부권 = L0만"* 이라 L0 는 돌아야 한다 | 없음 |

**따라서 예행 런은 다음 라운드가 아니라 네 모듈 뒤다.** 이 문장을 여기 적어 두는 이유는 §2 의 실측이
아니라 **낡은 좌표가 실제로 손해를 낸 전례** 때문이다 — 직전 라운드 감수 C′-2 가 P-5 를 부분으로
채점한 사유가 *"상위 기록이 여전히 Owner 대기 상태로 남아 있다"* 였다. 좌표가 낡으면 그 좌표를 읽는
판정이 함께 틀린다.

**★ 다만 「지금 아무 런도 못 돈다」는 아니다.** `'854` 통주 3 이 그랬듯 **READ 범위 부분 시험**은
지금 돌 수 있다. 그것은 예행 런이 아니고 그렇게 부르지도 않는다 — 격이 다르다. 소재
`WO2026128750A1` 로 그것을 지금 돌릴지가 §7 안건 ⑤다.

## §6 순서 — 세 안

### 안 ⓐ 명세 순서 그대로

```
PD-M2 → PD-M3 → PD-M4 → PD-M5 → PD-M9 → 예행 런
```

의존 그래프(§8.1)를 곧이곧대로 따른다. **문제**: PD-M4 를 지을 때 **판정 대상이 존재하지 않는다.**
L0 규칙 18종이 실제 스레드에 어떻게 걸리는지를 실물 없이 정하게 된다. 이 리포는 그 상태가 위험해서
**공허 통과 날인 기제**(`empty-target`)를 이미 입법해 두었다 — 그 기제가 필요했던 이유가 정확히 이
상태다.

### 안 ⓑ 게이트를 뒤로 — **총괄 추천**

```
PD-M2 → PD-M3 → PD-M5 → PD-M9 → PD-M4 → 예행 런
             (PD-M9 는 PD-M3 이후 아무 자리에나 병행 가능)
```

**근거 셋.**

1. **게이트에 실물 대상이 생긴다.** PD-M5 가 먼저면 PD-M4 의 회귀 코퍼스 golden 이 **실제 펜 산출**에서
   나온다. 합성 golden 은 「우리가 통과할 것이라 믿는 문장」이고 실물 golden 은 「펜이 실제로 쓴
   문장」이다. 판별력이 다르다.
2. **재정 조밀 구간을 뒤로 미루면 그 사이에 실측이 쌓인다.** 형식 파라미터 시트의 `[가설]` 항목들은
   실물 스레드를 보고 교정하는 편이 싸다(§8.6 이 이미 *"`[가설]` 태그 항목이 최우선 교정 후보"* 라고
   적어 둔 자리다).
3. **크리티컬 패스가 늘지 않는다.** PD-M4 와 PD-M5 는 의존 그래프상 형제다(둘 다 PD-M6 로 합류).
   순서를 바꿔도 간선을 어기지 않는다.

**반대 논거를 함께 적는다.** 게이트 없는 펜 산출은 **자기가 합법인지 모른다** — 3판 토너먼트를
돌리고 나서 L0 가 전부 거부할 수도 있다. 다만 예행 런은 **게시하지 않으므로** 그 손해는 토큰이지
출하물이 아니고, 오히려 그 거부 목록 자체가 PD-M4 의 회귀 코퍼스 mutated 가 된다.

### 안 ⓒ 병행 2레인

```
PD-M2 → ┌ 레인 A: PD-M3 → PD-M5 ┐ → PD-M4 → 예행 런
        └ 레인 B: PD-M9 ────────┘
```

벽시계는 줄지만 **총괄의 감독 하중이 겹친다.** PD-M1 라운드당 감독 레인이 30~50만 토큰이었고, 두
레인을 동시에 물면 결정 공백이 두 곳에서 동시에 올라온다. §8.6 이 병행을 허용하는 자리이긴 하나,
**총괄은 PD-M2~M5 구간에서는 권하지 않는다** — 병행의 값은 지구력이고, 이 구간의 병목은 지구력이
아니라 재정이다.

## §7 재정 안건 5건

각 안건은 **논점 · 선택지 · 총괄 추천 · 되돌리기 비용** 넷으로 적는다. 되돌리기 비용을 함께 적는
이유는 규율 11 ② 다 — *되돌리기 비용이 낮다는 것은 상신을 생략할 근거가 아니라 상신을 싸게 만드는
사실이다.*

### 안건 ① — PD-M2 의 경계: 재요리 경로를 지금 짓는가

**논점.** §4 ① 은 COMPOSE 가 없으면 실물 왕복 시험이 서지 않는다.

| | 선택지 | 무엇을 얻고 무엇을 잃는가 |
|---|---|---|
| **ⓐ** | **지금 짓는다** — 백로그 3건 + 재요리 + 절차 문서를 한 라운드로 | READ 맥락이 살아 있을 때 짓는다. 대신 시험이 합성 픽스처에 갇힌다 |
| **ⓑ** | **백로그 3건 + 절차 문서만** — 재요리 집행은 PD-M5 착지 시점으로 이연 | 재요리가 **실물 반려**로 시험된다. 대신 미결이 하나 더 오래 열려 있다 |
| **ⓒ** | PD-M2 를 라운드로 세우지 않고 PD-M3 발주에 흡수 | 라운드 수가 준다. 대신 성질이 다른 둘(방어층 보수 / 신규 저작)이 한 감수에 섞인다 |

**총괄 추천 = ⓑ.** 근거는 이 리포가 반복해 벌해 온 형태다 — **집행이 없는 선언**(B-2 의 성질,
M0.6 FAIL 사유)과 **실물로 시험되지 않은 구현**은 같은 부류의 부채다. 재요리를 합성으로만 시험하고
「구현되었다」로 적으면 §6.7 이 막으려는 자리를 스스로 밟는다. 절차 문서(②)는 재정 없이 지금 쓴다 —
문서는 실물 왕복을 요구하지 않는다.

**되돌리기 비용 = 낮음.** ⓑ 로 갔다가 나중에 앞당겨도 잃는 것이 없다.

### 안건 ② — B-1 판정 시점의 이동

**논점.** 검사(`read.py:1561~1562`)가 **메모리 저널**을 보고, 실제 로그는 그 뒤 `finally`(`:1618`)
에서 디스크에 쓰인다. **런 중 부정은 탐지되고 사후 편집만 탐지 밖이다.** 어느 층에서 무엇을 하는
검사인지가 재정 사항이다.

| | 선택지 | 결과 |
|---|---|---|
| **ⓐ** | **검사 대상을 기록본으로 옮긴다** — 로그를 먼저 쓰고 디스크 파일을 검사 | 런 중 거부 유지 + 사후 편집도 같은 검사가 잡는다. 쓰기 순서 변경이 필요하고 `finally` 의 실패 경로가 바뀐다 |
| **ⓑ** | **사후 재검 단계를 별도 배선** — 런 경로는 그대로, 종료 후 기록본을 재검하는 검사를 추가 | 러너를 안 건드린다. 대신 검사가 둘이 되고 **실패의 의미가 갈린다**(런 중 = 거부 / 사후 = 감사 보고) |
| **ⓒ** | 이연 유지 | 공격면이 열린 채 남는다 |

**총괄 추천 = ⓐ.** 근거: ⓑ 는 같은 불변식에 검사를 두 벌 두는데, **두 벌이 생기면 한 벌은 반드시
낡는다**는 것이 이 리포가 여러 자리에서 성문화한 원리다(`engine/gitpin.py` 단일 진원 · 형식 수치
시트 · 화이트리스트 B-07). ⓐ 는 검사를 하나로 유지한다.

**되돌리기 비용 = 중간.** 쓰기 순서 변경이 `finally` 실패 경로를 건드리므로 시험을 다시 짜야 한다.

### 안건 ③ — B-2 `lane_id` 값 공간 축소

**논점.** 계약(`read.yaml#lane.lane_id_vocabulary`)이 정본 형태를 선언하는데 집행이 없다. 다만
`lane_id` 는 `engine/lanes/plan.py:250 lane_id_for()` 가 **엔진 내부에서 조립**하고 조립 자리는
`plan.py:623` 하나뿐이라 **현재 진입 통로가 없다.** 집행을 켜면 **지금 통과하던 입력이 거부되기
시작한다** — 규율 11 의 값 공간 축소다.

| | 선택지 | 결과 |
|---|---|---|
| **ⓐ** | **계약 어휘 검증 + 루트 포함(containment) 강제** | 「선언은 있는데 집행이 없다」가 닫힌다. 현재 통로가 없으므로 **실질 회귀 위험이 거의 없다** |
| **ⓑ** | 이연 — 진입 통로가 없으니 급하지 않다 | 미결이 남는다. 나중에 외부 입력 통로가 생기면 그때가 가장 위험한 시점이다 |

**총괄 추천 = ⓐ.** 근거 둘 — ⑴ 성질이 M0.6 이 FAIL 을 낸 유형과 **같다**(강제 범위와 선언 범위의
불일치). ⑵ **지금이 가장 싸다.** 진입 통로가 없다는 것은 「고칠 필요가 없다」가 아니라 「고쳐도
아무것도 안 깨진다」는 뜻이다.

**되돌리기 비용 = 낮음.** 검증 한 블록.

### 안건 ④ — B-3: 「문서는 수를 적지 않는다」를 규율로 세우는가

**논점.** 이것만 성격이 다르다 — 코드가 아니라 **문서의 성격을 바꾸는 규율**이다. 실증은 이미 있다:
`441 → 452 → 464` 가 **한 라운드 안에서 두 번** 낡았고, 두 번 다 독립 감수가 잡았다. 고치는 시점과
늘어나는 시점이 다르므로 라운드를 더 돌아도 반복된다.

| | 선택지 | 결과 |
|---|---|---|
| **ⓐ** | **산문에서 수치를 뺀다** — 「시험 464건」 같은 계수를 문서가 적지 않고 도구 출력으로 대신한다 | 낡을 자리가 사라진다. 대신 **문서만 읽어서는 규모를 알 수 없다** |
| **ⓑ** | **자동 생성 + 관문 대조** — 계수는 한 블록에만 두고 `check_spec_refs.py` 가 실측과 대조해 어긋나면 exit 3 | 낡음이 **커밋 전에** 걸린다. 구현 비용이 있고, 대조 대상 목록 자체가 또 하나의 낡을 자리다 |
| **ⓒ** | **ⓐ + ⓑ 결합** — 산문에서는 빼고, 자동 생성 블록 **하나**에만 두고 그 블록을 관문이 대조 | 위 둘의 장점. 비용은 ⓑ 와 같다 |
| **ⓓ** | 현행 유지 — 정정 재량으로 계속 따라간다 | 실증상 **반복된다.** 이 선택지는 「반복을 수용한다」는 선언이다 |

**총괄 추천 = ⓒ.** 근거: 이 리포의 관문 철학은 *"각 도구는 하나의 주장만 증명한다"* 이고, 「문서의
계수가 실측과 같다」는 증명 가능한 주장이다. ⓐ 만으로는 규모를 잃고, ⓑ 만으로는 산문에 흩어진 수가
그대로 남는다.

**되돌리기 비용 = 중간.** 규율을 세우면 이후 모든 문서 작성이 그 규율 아래 놓인다. 다만 규율을
거두는 것은 한 줄이다.

### 안건 ⑤ — `WO2026128750A1` READ 부분 시험을 지금 돌리는가

**논점.** §3 이 정리했듯 예행 런은 네 모듈 뒤다. 그러나 **READ 범위 부분 시험**은 지금 가능하다
(`'854` 통주 3 과 같은 격 — 예행 런이 아니며 그렇게 부르지 않는다). 소재는 스테이징 완료
(`~/projects/workspaces/docent-rehearsal-01-source/input-raw/` · 본문 1,205행 3부 + 도면 20장).

**무엇이 걸려 있는가.** `'854` 는 OpenAI CIM — **하드웨어** 특허다. `WO2026128750A1` 은 DeepMind
ML 에이전트 기억 저장소 — **소프트웨어** 특허이며 청구항 구조가 전혀 다르다. READ 가 `'854` 에만
맞춰진 것인지 아닌지를 **아직 아무도 모른다.**

| | 선택지 | 결과 |
|---|---|---|
| **ⓐ** | **지금 돌린다** | READ 의 일반화를 지금 잰다. 신설 검사 `read.lane-log-digest-value` 가 실물에서 처음 돈다. CP1 판독본 2번째 실물이 생긴다. **비용 = 레인 왕복 7회 + CP1 검토 부담(판독본 10만 자급)** |
| **ⓑ** | PD-M2 와 **병행** | 벽시계 절약. 단 총괄 감독 하중이 겹친다(§6 ⓒ 와 같은 우려) |
| **ⓒ** | 예행 런까지 기다린다 | 한 번에 돈다. 대신 READ 의 소프트웨어 특허 취약점을 **네 모듈을 그 위에 얹은 뒤에** 발견하게 된다 |

**총괄 추천 = ⓐ (순차 · PD-M2 착수 전).** 근거: **결함은 위에 쌓기 전에 찾는 것이 싸다.** 그리고
이 시험이 실제로 무언가를 잡는다면 그 처분이 PD-M2 발주에 편입될 수 있다 — 순서가 반대면 편입할
자리가 없다. **다만 Owner 의 검토 부담이 실질 비용이다** — CP1 판독본은 지난번이 107,111 B 였고,
그것을 한 번 더 읽는 일이다. 그 부담을 총괄이 대신 질 수 없다(요약하면 「재료가 자족적인가」의 시험이
무효가 된다).

2. **`'854` M106 명명**(값 승인 · 명명 유보)과 **신설 검사의 증명 범위 경계**는 이월 상태 그대로

5. **총괄은 착수하지 않았다.** 코드 한 줄, 계약 한 줄도 건드리지 않았다. 이 문서와 그 커밋이 전부다.
